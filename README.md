# 뜨기 직전 유튜브 댓글 에이전트

조회수가 오르기 직전인 유튜브 영상을 먼저 찾아내고, AI가 영상을 직접 본 뒤 그 영상에 맞는 댓글을 다는 과정을 로컬에서 실행하는 대시보드입니다.

> **뜨기 직전 채널을 먼저 고르고, 새 영상이 올라오는 즉시 AI가 영상을 직접 보고 그 영상에서만 나올 수 있는 댓글 초안을 만드는 로컬 대시보드입니다.**
>
> ⚠️ 이 프로그램은 **YouTube에 아무것도 게시하지 않습니다.** 댓글 입력은 대시보드 안의 시뮬레이터에서만 일어나며, 서버 코드에는 YouTube 쓰기 API나 브라우저 자동 게시 경로가 없습니다.

## 1. 한눈에 보기

| 칸 | 하는 일 | 핵심 |
|---|---|---|
| ① 영상 불러오기 | 감시 채널의 최신 영상 목록 · 링크 직접 입력 · `뜨기 직전` 필터 · 감시 채널 순위 | 검색이 아니라 **채널 선점 + 업로드 감지** |
| ② 영상 선택 | 영상 속 고민 한 줄 · 장면 근거(타임스탬프·대사) · 댓글 초안 · 예상 반응 | Gemini가 **영상 자체**를 분석, Claude Opus 5.5가 작성, **민감 주제 자동 제외**, **Harness² 방식 작성 지침 자기 개선** |
| ③ 댓글 달기 | 영상 임베드 + 댓글 창에서 한 글자씩 자동 입력 → 시뮬레이션 등록 | **외부 전송 없음**, 규칙·기록은 실제로 강제 |

```
[채널 선정] 하루 1회
  연애·운세 후보 채널 수집 → 상승 신호 점수 → 상위 N개 감시
        ▼
[업로드 감지] 상시
  채널 RSS 확인 (막혀 있으면 Data API로 대체, 하루 예산에 맞춰 주기 자동 조정) → 새 영상 ID → 감지 지연 기록
        ▼
[민감 주제 필터] 제목·설명 키워드 → (통과 시) 영상 분석의 민감 판정
        ▼
[영상 분석] Gemini
  공개 영상 URL을 직접 입력 → 고민 한 줄 · 장면 3개 · 시청자 감정 (JSON)
  └ 업로드 직후 처리 실패 → 재시도 → 제목·설명으로 대체 (근거를 화면에 표시)
        ▼
[댓글 작성] Claude Opus 5.5 · 브랜드 방식 A 또는 B · 영역별 채택 하니스 적용
  후보 여러 개 → 형식 검증기 → 심사 모델이 1개 선택 + 예상 점수(예측치)
        ▲
[Harness² 개선] (버튼으로 실행) 같은 영상에서 작성 지침을 제안·시험·합성 → 채택·교훈 저장
        ▼
[웹 내부 시뮬레이터]
  페르소나 순환 배정 → 한 글자씩 입력 → 규칙 재검사 → 기록 (유튜브 미전송)
```

## 2. 빠른 시작

```bash
git clone https://github.com/TunaKimbab/jg-ai-pm.git && cd jg-ai-pm
python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env            # 키를 채우지 않으면 자동으로 목업 모드

.venv/bin/uvicorn app.main:app --port 8787
# 브라우저에서 http://localhost:8787
```

| 상황 | 설정 | 결과 |
|---|---|---|
| 키 없이 화면만 보기 | 아무것도 넣지 않음 | 목업 채널·영상·초안으로 세 칸이 끝까지 동작 |
| 실제 영상으로 실행 | `.env`에 `YOUTUBE_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY` | 실제 채널 감시·영상 분석·초안 작성 |
| 비용 아끼며 테스트 | `TEST_MODE=true` | 작성 모델이 `TEST_WRITER_MODEL`로 바뀜 |

테스트: `.venv/bin/python -m pytest -q`

## 3. 화면 사용법 (설명 없이 쓰는 순서)

1. 상단 오른쪽 **영상 형식**에서 자동(롱폼+숏폼)·롱폼만·숏폼만을, **브랜드 방식**에서 A(광고 표기)·B(맥락 댓글만)를 고릅니다.
2. **①** `영상 불러오기`를 누릅니다. 감시 채널의 최신 영상이 썸네일·제목·채널·날짜·길이와 함께 나타납니다.
   - `새로 감지` 탭: 서버가 켜져 있는 동안 새로 올라온 영상만 보여 주고, 감지까지 걸린 시간도 표시합니다.
   - `뜨기 직전` 탭: 조회수 1,000~5,000 · 시간당 150회 이상인 영상만 보여 줍니다.
   - `감시 채널` 탭: 채널 점수와 지표를 확인합니다. `채널 다시 고르기`로 순위를 새로 계산합니다.
   - `하니스` 탭: 영역(형식×방식)별로 채택된 작성 지침과 쌓인 교훈, 최근 개선 기록을 봅니다.
   - 링크 칸에 유튜브 주소를 붙여 넣으면 목록에 바로 추가됩니다.
3. **②** 영상을 고르면 분석 결과와 초안이 보입니다.
   - 초안이 없으면 `AI로 초안 만들기`를 누릅니다. 새로 감지된 영상은 자동으로 만들어집니다.
   - `Harness² 개선`을 누르면 이 영상으로 작성 지침을 개선하면서 가장 좋은 결과를 초안으로 씁니다(모델 호출이 약 8배).
   - 민감 주제로 제외된 영상은 회색 카드로 사유가 표시되며, 필요하면 `그래도 만들기`를 누를 수 있습니다.
   - 방식을 바꿨다면 `현재 방식으로 다시 만들기`로 초안을 새로 만듭니다.
4. **③** `댓글 달기`를 누르면 배정된 페르소나가 한 글자씩 입력하고, 끝나면 시뮬레이션으로 등록됩니다. 진행 단계(규칙 확인 → 입력 중 → 시뮬레이션 등록)가 실시간으로 바뀝니다.
5. 아래 **기록** 표에서 시각·영상·페르소나·댓글·결과를 시간순으로 확인합니다.

## 4. 채널 선정 개요

"이미 유명한 채널"이 아니라 **지금 커지고 있고, 연애·운세 관심층이 모이는 채널**을 먼저 고르는 것이 목표입니다. 여러 지표를 후보 채널 안에서 백분위로 바꿔 가중합합니다.

| 신호 | 보는 것 |
|---|---|
| 초기 속도 | 최근 영상이 게시 직후 얼마나 빨리 조회되는가 |
| 가속도 | 최근 영상이 이전 영상보다 빨라지고 있는가 |
| 도달률 | 구독자 밖으로 퍼지고 있는가 |
| 업로드 빈도 | 선점할 기회가 자주 오는가 |
| 주제 적합도 | 연애 고민·운세 콘텐츠 비중 |
| 규모 구간 | 유명하지만 아직 포화되지 않은 크기인가 |

- YouTube API는 구독자 증가 이력을 주지 않으므로, 매일 스냅숏을 저장해 이력을 직접 쌓습니다.
- 가중치는 측정으로 얻은 값이 아니라 **가정값**이며 화면에도 그렇게 표시합니다.
- 실제 점수식·검색어·가중치는 공개 저장소에 포함하지 않았습니다(아래 7절).

## 5. 브랜드 방식 (A / B)

| 방식 | 댓글 형태 | 검증 규칙 | 언제 쓰나 |
|---|---|---|---|
| **A · 광고 표기** | `[광고]`로 시작하고 영상 공감 뒤 설정한 브랜드(`BRAND_NAME`)를 소개 | 표기로 시작, 브랜드 언급 필수 | 실제 운영으로 이어질 수 있는 방식. 광고임을 밝혀 시청자를 속이지 않음 |
| **B · 맥락 댓글만** | 업체 이름 없이 영상에 공감하는 시청자 댓글 (인연·타이밍 이야기로 관심의 여지만 남김) | 업체 이름이 들어가면 탈락 | 영상 이해력과 댓글 품질을 보여 줄 때 |

- 기본값은 `.env`의 `BRAND_MODE`이며, 대시보드 상단 선택 상자로 실행 중에 바꿀 수 있습니다.
- 두 방식 모두 영상당 계정 하나(페르소나 하나)만 댓글을 답니다.
- 업체를 암시만 하고 다른 계정이 이름을 꺼내는 방식은 넣지 않았습니다. 작성 모델(Opus 5.5)도 이 방식을 "시청자를 속이는 바이럴 광고"로 판단해 쓰지 않았습니다.

## 6. 영상 형식 (자동 / 롱폼 / 숏폼)

| 설정 | 목록에 보이는 영상 | 새 영상 자동 초안 | 수동 초안 |
|---|---|---|---|
| **자동** | 롱폼 + 숏폼 (길이 미상 포함) | 모두 | 모두 |
| **롱폼만** | 롱폼만 | 롱폼만 (숏폼은 건너뛰고 이벤트에 기록) | 숏폼 요청은 거부 |
| **숏폼만** | 숏폼만 | 숏폼만 | 롱폼 요청은 거부 |

- 판별: `videos.list`의 `contentDetails.duration`으로 60초 이하는 숏폼, 3분 초과는 롱폼으로 봅니다. 그 사이는 `youtube.com/shorts/ID` 주소가 그대로 열리는지(숏폼) 다른 주소로 넘어가는지(롱폼)로 판별합니다(할당량 0).
- 롱폼은 Gemini가 앞 `LONGFORM_ANALYZE_MAX_SEC`초(기본 20분)만 분석해 시간과 비용을 제한하고, 장면을 앞·중간·뒤에서 고르게 고릅니다. 댓글도 숏폼은 짧고 즉각적인 반응으로, 롱폼은 특정 구간을 짚는 말투로 씁니다.
- 기본값은 `.env`의 `VIDEO_FORMAT`이며, 대시보드 상단에서 바꿀 수 있습니다.

## 7. 민감 주제 필터

자해·자살, 정신건강 위기, 중독(술·도박·약물), 폭력·학대·범죄 피해, 심각한 질병·사망·사별, 미성년자 연애를 다루는 영상에는 사주 유도 댓글을 만들지 않습니다.

| 단계 | 방식 | 비용 |
|---|---|---|
| 1 | 제목·설명 키워드 검사 | 없음 (Gemini 호출 전) |
| 2 | Gemini 영상 분석의 `sensitive` 판정 | 분석 1회 |

실제 테스트에서 "고1 때부터 술 마신 남친" 영상은 키워드 단계를 통과했지만, 영상 분석에서 "심각한 알코올 중독 및 일상 마비 문제"로 판정되어 제외되었습니다. `SENSITIVE_FILTER=false`로 끌 수 있습니다.

## 8. 댓글 생성 개요

| 단계 | 모델(기본값, `.env`로 교체) | 출력 |
|---|---|---|
| 영상 분석 | `gemini-3.8-flash` | 고민 한 줄, 장면 3개(시간·대사·키워드), 시청자 감정 |
| 댓글 작성 | `claude-opus-5-5` (adaptive thinking, effort `medium`) | 후보 여러 개 |
| 형식 검증 | 코드 | 방식별 규칙(A: 광고 표기·브랜드 언급 / B: 업체 이름 금지), 글자 수, 장면 언급, 타임스탬프 숫자 금지, 링크·해시태그 금지, **이용 후기처럼 지어낸 표현 금지**, 최근 댓글과의 유사도 |
| 심사 | `claude-sonnet-5-5` (effort `low`) | 최종 후보 + 예상 점수 |

- 장면은 분석 단계에서 실제로 확인된 것만 인용하게 하고, 검증기가 다시 대조합니다.
- Claude 호출은 structured outputs(JSON 스키마)로 받으며, 거절 응답에는 서버 측 대체 모델(`fallbacks`)을 켜 두었습니다.

## 9. Harness² 방식 작성 지침 자기 개선

Google Research의 [Harness²: Recursive Agent Harnessing for an Open World](https://github.com/google-research/harness2)(Apache-2.0) 알고리즘을 이 파이프라인에 맞게 옮겼습니다. 원 프레임워크는 Linux·Vertex AI·OpenCode/Codex 에이전트 실행기·벤치마크 채점기를 전제로 하므로 설치하지 않았고, 코드도 포함하지 않았습니다.

| Harness² 개념 | 이 프로젝트에서 |
|---|---|
| 하니스(모델 주변의 편집 가능한 구성 요소) | 작성 프롬프트에 덧붙는 JSON: 상시 지침(`system_addendum`) · 기억(`memory`) · 상황별 스킬(`skills: trigger → body`) |
| 작업 단위 재귀 Propose–Probe–Compose | 영상 하나에서 기본 실행 → **INV**(작성 절차)·**DOM**(실무 지식) 편집안 → 같은 영상으로 시험 → 합성안 실행 |
| 정답 없이 행동 대비로 판단 | 검증기 통과율·탈락 사유와 심사 점수(예측치)를 행동 증거로만 사용 |
| 하니스를 가린 결과물 선택 | 모든 실행의 최고 후보를 섞어 익명으로 심사 → 뽑힌 결과물을 낸 하니스를 그 영역의 하니스로 채택 |
| 하니스 개선 단계의 재귀 | 편집별 효과(helped / hurt / no observed effect / confounded)와 옮겨 갈 교훈 ≤1개를 영역별 라이브러리에 저장하고, 다음 개선이 먼저 읽음 |
| KEEP_BASE | 근거가 없으면 편집하지 않는 것도 정답으로 인정 |

```
영상 1개 (Gemini 분석은 1회만 하고 모든 실행이 공유)
  base 하니스 실행 ──→ 증거
        │
        ├→ INV 편집자 ─→ 편집안 실행 ─┐
        └→ DOM 편집자 ─→ 편집안 실행 ─┤  (병렬)
                                       ▼
                         합성 편집자 ─→ 합성안 실행
                                       ▼
                 하니스를 가린 결과물 선택 → 초안 + 채택 하니스
                                       ▼
                 경험 반영: 편집별 효과 + 교훈 → data/harness/<영역>/
```

**안전장치**
- 하니스는 필수 규칙(광고 표기, 업체 이름 금지/필수, 후기 지어내기 금지, 링크·해시태그, 글자 수)을 보충만 합니다. 충돌하면 필수 규칙이 우선하고, 검증기는 코드에 고정되어 하니스로 바꿀 수 없습니다.
- 편집자에게 기만 전술(업체 암시, 여러 계정 연출) 추가와 영상에 없는 사실 삽입을 금지합니다.
- 하니스 크기에 상한을 둡니다(상시 지침 600자, 기억 6개, 스킬 4개).
- 일반 초안 생성은 그 영역에서 채택된 하니스를 자동으로 씁니다(`HARNESS_ENABLED`).

**실제 실행에서 얻은 것 (2026-11-04, 숏폼·B 방식 영역에서 5회)**

| 회차 | 영상 | 실행별 통과 (base / INV / DOM / 합성) | 선택 | 채택 |
|---|---|---|---|---|
| 1 | 식음전폐한 여친 위로 | 3/3 · 기본 유지 · 3/3 · 3/3 | base | – |
| 2 | 남자 방치하는 여자 사주 | 2/3 · 2/3 · 2/3 · 기본 유지 | base | – (교훈 1) |
| 3 | 많이 놀아본 사람일수록 바람을 안 필까? | 2/3 · 3/3 · 2/3 · 3/3 | 합성 | ✅ |
| 4 | 며칠 만에 신혼집 알아보는 돌싱남 | 3/3 · 기본 유지 · 3/3 · 3/3 | DOM | ✅ (교훈 2) |
| 5 | 의문의 1패를 남긴 오션뷰 프러포즈 | 3/3 · 기본 유지 · 기본 유지 · – | base | – |

- 채택된 하니스는 실제 실행에서 드러난 문제를 규칙으로 바꿨습니다. 기본 하니스 결과에서 작성 모델이 장면 목록에 없는 상황("아내는 자고 있는데")을 지어내자 금지 규칙을 넣었고, 훈계조로 끝나는 습관은 "마지막 문장은 보는 사람의 감정 반응으로 끝낸다"는 스킬로 고쳤습니다.
- 5회차에서는 편집자 둘 다 "근거 부족, 기본 유지"로 답했고, 채택된 하니스로 쓴 기본 실행이 이번 영역에서 가장 높은 예측 점수(자연 4.0 · 맥락 4.33)를 냈습니다. 다만 영상이 매번 달라 하니스 효과만 분리한 결과는 아닙니다(confounded).
- 2회차의 편집 효과 기록은 **검증기 결함**을 짚었습니다. 장면 대사를 원문 그대로 인용해도 '장면 키워드 미포함'으로 탈락했는데, 검증기가 대사는 보지 않고 분석 단계의 키워드 목록만 대조했기 때문입니다. 지금은 대사 구절을 그대로 인용해도 장면 언급으로 인정하고, 회귀 테스트를 추가했습니다.
- 공개본(core 없음)에서는 `Harness² 개선` 버튼과 `하니스` 탭이 숨겨집니다.

## 10. 운영 규칙과 기록

| 규칙 | 강제 방식 |
|---|---|
| 영상당 1개 | SQLite `PRIMARY KEY(video_id)` + 입력 전·후 이중 검사 |
| 하루 상한 (기본 10) | 등록 시점에 오늘 건수를 세어 초과하면 거부 |
| 페르소나 순환 | 영상마다 유튜브1 → 2 → 3 순서로 배정, 한 영상에는 한 페르소나만 |
| 기록 | 시각·영상·페르소나·구분·댓글·결과(`simulated` / `failed`)를 시간순 저장 |

**실측과 예측을 섞지 않습니다.**

| 값 | 성격 |
|---|---|
| 입력 결과, 규칙 차단, 감지 지연, 조회수 | 실측 |

| 채널 점수 가중치 | **가정값** |

링크가 없는 댓글이 실제로 방문을 만들었는지는 이 프로그램으로 측정할 수 없습니다. 그래서 유도 효과는 예측치로만 다루고, 그 사실을 화면에 표시합니다.

## 14. 설계 원칙

1. **선점이 품질보다 먼저입니다.** 같은 댓글도 영상이 뜨기 전에 달려야 위로 올라갑니다. 그래서 "어떤 영상을 고를까"를 키워드 검색이 아니라 *상승 채널 감시 + 업로드 즉시 감지*로 바꿨습니다.
2. **영상을 직접 봐야 그 영상만의 댓글이 나옵니다.** 업로드 직후에는 자막과 인기 댓글이 없으므로, Gemini가 화면과 음성을 직접 분석하게 했습니다. 실패하면 제목·설명으로 대체하고 그 사실을 표시합니다.
3. **쓰는 모델과 고르는 모델을 나눴습니다.** Opus 5.5가 여러 후보를 쓰고, 코드 검증기가 규칙 위반을 걸러 내고, 별도 심사 모델이 고릅니다. 모델은 모두 `.env`로 교체할 수 있습니다.
4. **광고는 광고라고 밝히고, 민감한 사연은 건너뜁니다.** A 방식은 `[광고]` 표기를 강제하고, 중독·폭력 같은 고통을 다룬 영상에는 아예 초안을 만들지 않습니다.
5. **실제 게시는 하지 않았습니다.** 다른 사람의 영상에 자동으로 댓글을 남기는 것은 YouTube의 스팸·가짜 참여 정책에 걸리고, 광고 목적을 밝히지 않으면 추천·보증 표시 의무 문제가 생길 수 있습니다. 그래서 입력 과정은 웹 내부 시뮬레이터로 보여 주고, 규칙과 기록은 실제와 똑같이 강제했습니다. 실제 운영으로 전환한다면 광고 표기와 플랫폼 정책 검토가 먼저입니다.
6. **측정할 수 없는 것은 예측치로 표시했습니다.** 링크 없는 댓글의 유도 효과는 측정할 수 없으므로 LLM 심사 점수를 *예측치*로만 보여 줍니다.
7. **작성 지침도 스스로 다듬게 했습니다.** 새 영상은 매번 처음 보는 작업입니다. Harness² 방식으로 같은 영상에서 지침을 제안·시험·합성하고, 근거가 있는 교훈만 영역별로 쌓아 다음 영상에 넘깁니다. 근거가 없으면 바꾸지 않습니다.

## 16. 한계

- RSS가 막혀 API로 감시할 때는 할당량 때문에 확인 주기가 수 분 단위로 늘어납니다. WebSub 실시간 알림은 외부 공개 주소가 필요해 넣지 않았습니다.
- B 방식은 브랜드를 언급하지 않으므로 '브랜드 유도' 점수는 낮게 나올 수 있습니다.
- 공개 영상만 분석할 수 있습니다. 업로드 직후에는 Gemini 처리가 실패할 수 있습니다.
- 예상 점수는 실제 시청자 반응이 아닙니다.
- Harness² 개선은 영상마다 실행 1회라 편집 효과 대부분이 confounded로 기록됩니다. 하니스 효과를 분리하려면 같은 영상 묶음으로 채택 전후를 비교해야 합니다.
